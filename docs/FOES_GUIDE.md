# 몬스터 제작 가이드 (1지역에서 확정된 방식)

1지역 「잿빛 마을」 9종(일반 6 · 정예 2 · 보스 1)에서 사용자에게 "아주아주 잘했다"는 평을 받은 방식이다. 2~12지역도 이 문서대로 만든다.

## 0. 사용자가 원하는 것 (절대 기준)
- **스컬 수준의 몬스터·보스**. 레퍼런스: 붉은 드래곤 그림(매끈한 입체 명암, 강한 테두리 빛, 굵은 실루엣).
- **시각이 최우선**, 그다음이 애니메이션. "뭘 하려는지 동작만 보고 알 수 있어야" 한다.
- 개성 있고 이야기가 있고 싸울 맛 나는 적. 패턴과 이야기는 `src/forge/regions.json`(설계서)에 이미 있다. 그대로 구현한다.
- **하지 말 것**: 몬스터 위 글자(이름표, "빈틈!", "!" 등), 몬스터를 감싸는 빛 테두리(preFX glow), 몸 전체가 붉게 깜빡이는 효과, 2단계 보스 전체 색칠. 바닥의 공격 범위 경고선은 괜찮다.

## 1. 파일 구조
| 파일 | 역할 |
|---|---|
| `src/forge/foes/r3d.js` | 3D → 픽셀 렌더러 (도형, 빛, 외곽선) |
| `src/forge/foes/rig.js` | 공용 재질 결(veins/rough/plates/cloth), 망토, 걷기 위상, 다리·팔 도우미 |
| `src/forge/foes/core.js` | 등록(register), 시트 생성(build3d), 생성기 AI 실행(think), 애니메이션(anim), 행동 도구(A), 적 쪽 위험 지대 |
| `src/forge/foes/m0.js` | 1지역 몬스터 3D 모델 |
| `src/forge/foes/r0.js` | 1지역 몬스터 행동(AI) — `register(id, { ...모델, speed, brain, ... })` |
| `src/forge/foes/boss0.js` | 1지역 보스 모델 + 패턴(async, 엔진 보스 도구 사용) |
| `src/forge/glue.js` | 엔진 연결(foeDef/foeThink/foeAnim/foeBlocks/foeDamage/foeDie/foeBoss/foeHurt/foeFrame), BOSS_RUN 표 |

새 지역 n을 만들 때 (2~4지역에서 굳힌 순서):
1. `m{n}.js`: 9종 3D 모델 (보스 포함, 보스는 `boss: !0`). **몬스터마다 따로 설계** — 실루엣·얼굴·고유 부위·재질·고유 동작이 서로 달라야 한다(사용자가 "비슷하게 만들지 말라"고 분명히 함).
2. `models.js`에 9종 등록 (워커가 이 표로 렌더한다).
3. `r{n}.js`를 임시 행동으로 등록 → **갤러리로 그림부터 확인·수정** → 그다음 행동 작성.
4. `boss{n}.js`에 `bossRun{n}` 작성, glue.js에서 import + `BOSS_RUN`에 추가 + `FOES.register("frb{n}", 모델)`, `world.js`의 `BOSS[n]` 패턴 이름 교체(1단계 3개 + 2단계 3개).
5. step → 전투 스크린샷 → 보스 아레나 시험(아레나 위치: 1지역 520, 2지역 1320, 3지역 2112, 4지역 2920, 5지역 3840, 6지역 4744, 7지역 5632, 8지역 6440, 9지역 7232, 10지역 8136 근처 — `debugTeleport(아레나-15)`) → 멈춤 봇 → 배포. id는 일반 `fr{n}_{0..5}`, 정예 `fr{n}_e{0,1}`, 보스 `frb{n}`.

## 2. 렌더러 (r3d.js)
- 좌표: x 오른쪽, y 아래, **z 보는 사람 쪽**. 단위 = 픽셀. 바닥 = `fh-2` 근처, 가운데 = `fw/2` 근처(프레임 원점은 발밑 가운데).
- 도형: `M.sphere(c, r, mat)`, `M.ell(c, [rx,ry,rz], mat, rotZ, tiltX)`, `M.cap(a, b, ra, rb, mat)`(끝이 둥근 원뿔원기둥 = 팔다리·뿔·발톱), `M.box(c, half, mat, rotZ, rotY)`.
- 칠하기: 왼쪽 위 앞 빛 + 감싸는 빛 → 재질 단계(tones)로 끊기 + 약한 디더링, 오른쪽 뒤 테두리 역광(rim), 작은 반사광(spec), 주변광 차폐(앞에 있는 면이 있으면 어둡게), 바깥 외곽선 + 깊이 차 큰 곳 안쪽 선.
- 재질: `mat(색, { tex, spec, shin, rim, rimCol, emit, tones })`. `emit`은 스스로 빛남(눈·불씨·균열). `tex(u,v,w,seed)`는 **도형 지역 좌표**라서 애니메이션해도 결이 흐르지 않는다.

## 3. 디자인 규칙 (이게 품질을 만든다)
1. **3/4 각도**: 얼굴(눈구멍·눈·입)을 +x(앞)뿐 아니라 **+z(보는 쪽)로 4~6 당겨** 놓는다. 안 그러면 뒷모습처럼 보인다.
2. **앞쪽 팔다리 z=+4~8, 뒤쪽 z=−4~8**. 뒤쪽은 더 어두운 재질을 써서 깊이를 준다.
3. **상자는 칼날·판에만**. 투구·흉갑·방패는 타원체(납작하게)로 만든다. 상자로 만들면 납작하고 각져 보였다.
4. **반사광은 작게**: spec 0.3~0.4, shin 40 이상. 크면 하얀 구슬처럼 튄다.
5. **표면 결은 약하게**: tex 진폭이 크면 자글자글해진다. plates는 -0.7/0.4 정도.
6. **포인트는 빛나는 재질**: 눈, 불씨, 용암 균열(veins), 달아오른 칼날 가장자리 같은 것. 칼 전체를 주황으로 칠하면 나무처럼 보인다. 칼날은 강철 그대로 두고 가장자리에만 빛나는 선을 넣는다.
7. **망토**는 `cape()`(얇은 타원체를 이어 붙이고 끝단 너덜너덜). 큰 타원체 하나로 만들면 붉은 달걀처럼 보인다.
8. **두건·투구가 얼굴을 가리지 않게** z를 뒤로(−3~−4) 뺀다. 해골 궁수 두건이 두개골을 덮었던 실수가 있었다.
9. 크기: 일반 프레임 48~72, 정예 80~84, 보스 130×110 정도. 몸 판정(w,h)은 그림보다 조금 작게.
10. 지역 색: 재료 색으로 지역 분위기를 낸다(1지역 = 재·검댕·잿불 주황).

## 4. 애니메이션 규칙
- `anims: { 이름: [장수, fps, 반복여부] }`. 필수: `idle`(4~6), `move`(6~8), `hurt`(2). 엔진이 경직 때 `hurt` 첫 장을 쓴다. 보스는 `stagger` 필수.
- 공격은 반드시 **예고(wind) → 타격(atk, 빠른 fps) → 여운(rec)** 세 단계로 나눈다. 예고는 크게 과장한다(몸을 젖힘, 무기를 머리 위로, 몸을 낮춤). 타격은 2~4장에 14~18fps.
- 걷기: `gait(위상, 보폭, 들기)`로 다리를 움직이고, 몸 위아래(bob)와 팔을 반대로 흔든다.
- 고유 동작은 따로 만든다(쥐 물고 빠지기 back, 궁수 공중제비 hop, 종 울리기 ring, 파수꾼 무릎 stun 등).
- 모델 함수 안에서 `nm`(동작 이름), `k`(몇 번째 장), `n`(장수)로 포즈를 계산한다. `ease`, `lerp`를 쓴다.

## 5. 행동(AI) 규칙
- `*brain(e, A)` 생성기. `yield 초`로 기다리고, `yield 0`은 다음 프레임이다. 맞아서 경직되면 core가 생성기를 버리고 처음부터 다시 생각한다(예고 중에 맞으면 공격이 끊김).
- 주요 도구:
  - 이동: `A.walk(방향, 속도)`, `A.stop()`, `A.flyTo(x,y,속도)`
  - 방향·거리: `A.face()`, `A.dx`/`A.dy`/`A.dist`
  - 동작: `A.play(이름)`(반복), `yield A.once(이름)`(한 번 재생하고 끝까지 기다림), `A.hold(이름, k)`
  - 예고: `A.tele(초, { bar: [x, 폭] })`
  - 공격: `A.melee(폭, 높이, 배율, { el, st, knock })`, `A.shoot(...)`, `A.zone(...)`(적 쪽 불길)
  - 연출: `A.fxSlash`, `A.fxHeavy`, `A.burst`, `A.shake`, `A.sound`
- 특수 규칙은 spec 훅으로 넣는다: `damage(e,dmg,C)`(등 2배, 종이 대신 맞기), `blocks(e,S)`(방패), `die(e,A)`(부활, 불길), `tick(e,A)`(매 프레임), `init(e,A)`.
- 보스: `bossRun(b, 이름, R)`. 엔진 보스 도구(`b.wait`, `b.warnBar`, `b.warnCircle`, `b.hitRect`, `b.wave`, `b.summon`, `b.walkTo`, `b.clampX`)를 쓰고, 프레임은 `b.frame(F("이름", k))`로 지정한다. 2단계 기술은 1단계에서 1단계 기술로 바꾼다. 2단계 첫 행동은 연출 있는 기술(소환 등)로 한다.

## 6. 검증 절차 (매 지역 반드시)
`tools/README.md`의 헤드리스 크롬 + `tools/cdp.mjs`를 쓴다.
1. 빌드한 뒤 **갤러리**로 모든 동작을 1배와 3배로 본다. 이상하면 고치고 다시 본다(1지역은 3번 고쳤다).
2. 콘솔에 `foe model ...` 경고가 없어야 한다. 경고가 있으면 모델 함수에서 오류가 난 것이고, 그 동작은 투명하게 나온다.
3. **step.js**로 몬스터마다 update를 돌려 오류가 없는지 본다.
4. **전투 장면**에서 소환해 스크린샷을 찍는다.
5. 보스는 아레나로 이동(`debugTeleport`)해 패턴과 2단계 전환을 본다.
6. 배포: `vercel deploy --prod --yes`.

## 7. 겪은 함정
- 모델 함수 안 지역 변수 이름이 가져온 함수 이름과 겹치면(`cape`) 모델 전체가 실패한다. `cape` 변수는 `cp`로 바꿔서 고쳤다.
- 엔진 경직 프레임은 원래 숫자 8, 보스 경직은 7이었다. 새 몬스터는 `foeHurt`/`foeFrame("stagger")`로 바꿨다.
- 엔진 HUD 이동 코드가 x<236, y<72인 물체를 아래로 옮기니, 폭이 넓은 보스 체력바는 제외해야 한다(ui.js).
- 부팅 렌더링 시간: 1지역만으로 헤드리스 기준 약 5초. 지역이 늘면 **그 지역에 처음 들어갈 때 렌더링**하도록 바꿔야 한다(TODO).

## 8. 성능 · 멈춤 (2026-11-15 정리)
- **완전 멈춤의 원인은 "매 프레임 반복되는 오류"**다. 장면 update에서 오류가 나면 다음 프레임에도 같은 오류가 나서 게임이 멈춘 것처럼 보인다. 이름표를 `false`로 바꿨다가 `label.destroy()`/`setText()`에서 터진 적이 있다. 없앨 때는 `undefined`로 둔다.
- `tools/foetest/bot.js`: 오른쪽으로 계속 달리며 싸우고, 상자를 열고, 카드를 고르고, 가끔 하늘·지하로 이동한다. 오류, 250ms 넘는 프레임, 진행 멈춤을 기록한다. **큰 변경 뒤에는 반드시 돌린다** (`window.__SEC=100;`을 앞에 붙임).
- `tools/profile.mjs`: 스크립트를 CPU 프로파일러로 돌려 오래 걸린 함수를 보여 준다. 짐작하지 말고 재 볼 것. 헤드리스는 GPU 작업이 CPU 흉내라 `(program)`, `texImage2D`가 부풀려진다.
- 지형 그리기(terrain.js)는 생성기 `paintSteps`로 나눠져 있고, 월드가 다음 구역(T+4, T−3)을 프레임마다 5ms씩 **미리 그린다**(prepaint). 새 그리기 단계를 넣으면 열마다 `yield`가 걸리도록 한다.
- 둥근 돌 명암은 `lvTile(G)` 반복 타일에 한 번만 계산한다.
- 다음 지역 배경은 **웹 워커**(`bgworker.js`, `AiAsync`)에서 그린다. 배경 그리기 코드(bgnew/bg3d)는 화면에 손대지 않는 순수 계산으로 유지해야 워커에서 돈다.
- 몬스터 시트는 **워커(`foes/foeworker.js` + `sheet.js` + `models.js`)**에서 렌더한다. 부팅 때 1·2지역, 지역에 다가가면 다음 지역을 미리 만든다(`preloadRegion`). 아직 안 됐는데 몬스터가 생기면 그 자리에서 만든다(`ensure`, 엔진 Cs/보스 생성자에 연결). 부팅 시간 6초 → 1.4초.
- 공용 도구 추가: `A.blind(초)`(시야 축소), `A.afflict(상태)`(플레이어 상태이상, 속박은 stun), 적 `_stoneUntil`(돌 갑옷 피해 절반).

## 9. 5~7지역에서 배운 것 (2026-11-15)
- `python tools/addregion.py <n> <모델 9개>` 로 등록·임시 행동 파일을 한 번에 만든다. 보스는 glue `BOSS_RUN`과 world.js `BOSS[n]` 패턴 배열을 직접 바꾼다.
- 그림 다듬기는 **개발 서버(5173)** 로 하면 빌드(3분) 없이 바로 본다: 페이지를 `location.href="http://localhost:5173/"` 로 옮기고 갤러리 실행.
- 치마·드레스는 타원을 띄엄띄엄 쌓으면 "층층이 갓" 모양, 캡슐 하나면 "가지" 모양이 된다. **얇은 원판(세로 1.6)을 25장 촘촘히** 쌓는다.
- 날개는 접힘/펼침(가운데·위·아래) **열쇠 자세 점들을 섞는** 방식(kryos `WK`, 박쥐 `P(U,D)`)이 가장 잘 나온다. 막은 손목에서 부채꼴로 작은 타원.
- 시트는 가로 2048px 넘으면 여러 줄로 감긴다(sheet.js). 모바일 텍스처 한도 때문.
- 텍스처를 지울 때(지역 배경 정리, 몬스터 시트 교체) 그 텍스처를 쓰는 물체가 **어느 장면에든** 남아 있으면 다음 렌더에서 `glTexture` 오류로 멈춘다. 지우기 전에 모든 장면의 표시 목록을 확인한다.
- 군기 버프: 적의 `_rallyT`가 남아 있으면 think가 시간을 1.3배로 흘린다.
